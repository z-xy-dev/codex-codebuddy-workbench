# CodeBuddy Workbench 插件 · 操作说明

一个让 Codex 用上 **CodeBuddy 风格布局** 的插件：左侧文件树（带 git 状态）、右上文件预览、右下真实终端、右侧接真 Codex 的聊天栏。布局开在独立的浏览器窗口里（不是替换 Codex 自身窗口）。

本说明分三部分：
- **一、非技术人员**：照着点就行，不用懂命令
- **二、技术人员**：命令行安装、指定目录、原理
- **三、怎么用工作台（两种打开方式）**

---

## 一、非技术人员（纯界面，不用敲命令）

> 适用：已经拿到了这个插件文件夹 `codex-codebuddy-workbench`，想在 Codex 里用起来。

### 方法 A：让 Codex 自己安装（最简单，但需要 Codex 桌面应用）

1. 把整个 `codex-codebuddy-workbench` 文件夹放到一个**不会随便删除**的地方（例如 `桌面` 或 `文档` 里都行）。
2. 打开 **Codex 桌面应用**，在对话框里直接发一句话：
   > 安装这个插件：把 `C:\你放的位置\codex-codebuddy-workbench` 作为 marketplace 加入并安装 codex-codebuddy-workbench
   （把路径换成你实际的路径。Codex 会自己执行安装命令。）
3. 安装完成后，对话框里再发：
   > 用 CodeBuddy 布局打开当前项目
4. 稍等几秒，你的**默认浏览器**会自动弹出一个工作台窗口（左文件树 / 中预览 / 下终端 / 右聊天）。这就成功了。

> 如果 Codex 没有自动安装，改用下面的方法 B 或第二部分命令行。

### 方法 B：用安装脚本（双击即可，无需懂命令）

1. 在 `codex-codebuddy-workbench` 文件夹里新建一个文件，命名为 `安装.bat`（注意后缀是 `.bat`）。
2. 用记事本打开它，粘贴下面这段，把 `C:\换成你实际的\codex-codebuddy-workbench` 改成文件夹真实路径，保存：

   ```bat
   @echo off
   codex plugin marketplace add "C:\换成你实际的\codex-codebuddy-workbench"
   codex plugin add codex-codebuddy-workbench@codex-codebuddy-workbench
   echo.
   echo 安装完成。在 Codex 里说"用 CodeBuddy 布局打开当前项目"即可。
   pause
   ```
3. **双击** `安装.bat` 运行。黑窗口出现 "安装完成" 就成功了（如果提示 `codex 不是内部命令`，说明 Codex 没装好或没进 PATH，先用 Codex 桌面应用）。
4. 之后在 Codex 对话框说 "用 CodeBuddy 布局打开当前项目" 即可使用。

### 卸载（非技术）

在 Codex 对话框里发：
> 卸载 codex-codebuddy-workbench 插件

## 二、技术人员（命令行）

### 方法 1：从本地文件夹导入（marketplace 方式，推荐）

```bash
# 1) 把插件所在的文件夹作为本地 marketplace 加入
codex plugin marketplace add "C:\路径\到\codex-codebuddy-workbench"

# 2) 安装插件（插件名已固定为 codex-codebuddy-workbench，marketplace 名为 codex-codebuddy-workbench）
codex plugin add codex-codebuddy-workbench@codex-codebuddy-workbench
```

`codex-codebuddy-workbench/` 是 marketplace 根目录，里面必须有 `.agents/plugins/marketplace.json`。安装后插件被缓存到：
`~/.codex/plugins/cache/codex-codebuddy-workbench/codex-codebuddy-workbench/0.1.0/`

### 方法 2：导入到「指定目录」并绕过 marketplace

适合想直接放进用户插件目录、不注册 marketplace 的场景。

> ⚠️ **关键坑**：marketplace 名称是全局唯一的。直接复制文件夹再 `marketplace add` 会因为同名
> `codex-codebuddy-workbench` 冲突而报 *"already added from a different source"*。
> 因此「指定目录法」要用**不冲突的 marketplace 名**，改两处即可。

步骤：

1. 复制整包到目标目录，例如 `%USERPROFILE%\.codex\plugins\manual\codex-codebuddy-workbench`
2. 编辑里面的 `.agents/plugins/marketplace.json`，把两处名字改掉（避免冲突）：
   - `"name": "codex-codebuddy-workbench"` → 改成 `"name": "my-local-buddy"`
   - 该文件里 `plugins[].name` 保持 `codex-codebuddy-workbench` 不变也行
3. 同样改 `.codex-plugin/plugin.json` 里的 `"name"` 可保持 `codex-codebuddy-workbench`（与 marketplace 内的名字一致即可，跨 marketplace 不冲突）

   ```bash
   # 注册这个指定目录为 marketplace（用新名字 my-local-buddy）
   codex plugin marketplace add "%USERPROFILE%\.codex\plugins\manual\codex-codebuddy-workbench"

   # 安装（插件名@新 marketplace 名）
   codex plugin add codex-codebuddy-workbench@my-local-buddy
   ```

### 方法 3：直接丢进 plugins 目录（免 marketplace，最简但不可通过 CLI 升级）

Codex 的插件缓存/用户目录是 `~/.codex/plugins/`。把插件本体复制进去即可被发现：

```bash
# 复制插件「本体」（含 .codex-plugin/ 的那一层）到用户插件目录
cp -r "C:\路径\到\codex-codebuddy-workbench\plugins\codex-codebuddy-workbench" "%USERPROFILE%\.codex\plugins\codex-codebuddy-workbench"
```

然后 `codex plugin add codex-codebuddy-workbench` 或直接重启 Codex 桌面应用即可生效。
（注意：从 plugins 目录直接加载时，插件里的 skill 路径仍是 `skills/codebuddy-workbench/...`，与包内结构一致，无需改 marketplace.json。）

### 常用命令

```bash
codex plugin list                                  # 列出已安装的插件
codex plugin remove codex-codebuddy-workbench@codex-codebuddy-workbench   # 卸载
codex plugin marketplace list                      # 查看已注册的 marketplace
codex plugin marketplace remove codex-codebuddy-workbench         # 移除 marketplace 源

# 更新插件（见下方「更新插件」一节）
codex plugin remove codex-codebuddy-workbench@codex-codebuddy-workbench
codex plugin add codex-codebuddy-workbench@codex-codebuddy-workbench
```

## 二·五、更新插件（改了代码怎么生效）

> ⚠️ **关键认知**：`codex plugin add` 安装时，会把源目录**复制**一份到 Codex 的缓存目录，工作台真正跑的是那份缓存，**不是你桌面上编辑的那份**。两份是独立的；你只改桌面源目录，工作台不会变。

缓存目录位置（Windows）：

```
C:\Users\你的用户名\.codex\plugins\cache\codex-codebuddy-workbench\codex-codebuddy-workbench\0.1.0\
```

### 场景 1：你改了源码，想让工作台用上新功能（如 Git 提交图）

**方法 A（推荐）：重新 add 覆盖缓存**
```bash
codex plugin remove codex-codebuddy-workbench@codex-codebuddy-workbench
codex plugin add codex-codebuddy-workbench@codex-codebuddy-workbench
```
用桌面源目录重新生成缓存，等价于"更新"。marketplace 不需要再 add。

> ⚠️ **如果 remove 报 `拒绝访问 (os error 5)`**：是工作台服务还在跑，占着缓存目录里的文件（Windows 锁住正在使用的文件）。先停掉服务再更新：
> ```bash
> taskkill /PID <state.json里的pid> /F
> ```
> 服务状态文件在 `C:\Users\你的用户名\.codex\codebuddy-workbench\state.json`，里面的 `pid` 字段就是要杀的进程号；或者直接在 Codex 里说「关闭工作台」。停完再执行上面两条命令。

**方法 B：直接把文件拷进缓存目录**
把这三个文件从源目录覆盖到缓存目录同名位置即可（无需重装）：
- `plugins/codex-codebuddy-workbench/skills/codebuddy-workbench/server/server.js`
- `plugins/codex-codebuddy-workbench/skills/codebuddy-workbench/web/app.js`
- `plugins/codex-codebuddy-workbench/skills/codebuddy-workbench/web/index.html`

> 因为改了 `server.js`（不只是前端），**必须重启服务**才能生效：在 Codex 里「关闭工作台」再「打开工作台」，或杀掉旧的 `node server.js` 进程。

### 场景 2：想一劳永逸，改完即时生效

那就**直接编辑缓存目录那份**（`0.1.0/` 里），改完重启工作台即生效，不用任何拷贝/重装。
代价：换电脑或清掉缓存后，要从源目录用方法 A 重新安装一次。

### 怎么判断现在工作台跑的是哪份？

- 在缓存目录那份里搜一下你新增的代码（例如 `api/git-graph`），**搜不到 = 还在跑旧版**，需要先更新（场景 1）。
- 搜得到但功能没出现 = 服务没重启，回 Codex 说「关闭工作台 / 打开工作台」。


### 目录结构（交付物）

```
codex-codebuddy-workbench/                      ← marketplace 根（marketplace add 指向这里）
├─ .agents/plugins/marketplace.json
└─ plugins/codex-codebuddy-workbench/          ← 插件本体
   ├─ .codex-plugin/plugin.json
   ├─ README.md
   ├─ browser.mjs                 # 零依赖 Chromium CDP 驱动（AI/脚本用）
   ├─ scripts/smoke.mjs           # 零依赖全链路自检脚本
   ├─ assets/{icon.png,logo.png}
   └─ skills/codebuddy-workbench/
      ├─ SKILL.md                        # Codex 技能说明（"打开工作台"会触发它）
      ├─ server/server.js                # 零依赖本地服务（HTTP + WS + 真实终端 + 聊天桥）
      ├─ server/node-pty/                # 随插件打包的终端原生模块（win32-x64 预编译）
      └─ web/                            # 前端界面（index.html / app.js / vendor 库）
```

## 三、怎么用工作台

安装好后，有两种打开方式：

### 方式 1：在 Codex 里说一句话（推荐）

在 Codex 对话框里发：

- **"用 CodeBuddy 布局打开当前项目"**（或"打开工作台布局"）
  → Codex 会在后台起服务，并自动在你的浏览器打开工作台窗口。
- **"关闭工作台"** → 停掉后台服务。

### 方式 2：自己手动起服务

需要控制项目目录或端口时，直接跑 Node（脚本零依赖，只要系统 Node ≥ 18）：

```bash
# 用已安装的插件路径
node ~/.codex/plugins/cache/codex-codebuddy-workbench/codex-codebuddy-workbench/0.1.0/skills/codebuddy-workbench/server/server.js \
     --daemon --root "你的项目目录"

# 浏览器会自动打开它打印的地址，形如 http://127.0.0.1:5399/?token=...
# 关闭：
node ~/.codex/plugins/cache/codex-codebuddy-workbench/codex-codebuddy-workbench/0.1.0/skills/codebuddy-workbench/server/server.js --stop
```

### 界面操作速记

| 区域 | 能做什么 |
|---|---|
| 左·文件树 | 点文件夹展开、点文件预览；底部 git 栏显示分支与改动数；"问题"面板可点跳转到改动文件 |
| 中上·预览 | 多标签页，支持 代码 / Markdown / 图片 / PDF；Markdown 里的相对链接可点跳转 |
| 中下·终端 | 标签页里可选 PowerShell 7 / cmd / bash；右上"＋"新建、"🗑"结束；整栏可用标题栏"⌨ 终端"按钮隐藏 |
| 右·聊天 | 像普通对话框提问；下方选沙箱档位（默认 workspace-write）；**模型下拉**默认"跟随配置"（即 `~/.codex/config.toml` 里的 model），可独立选择覆盖；"＋ 新会话"清上下文；运行中按 Esc 或点 ■ 停止 |
| 标题栏 | "📁文件树 / ⌨终端 / 💬对话"三个开关可隐藏对应区；拖动分隔条可调宽度，状态记在浏览器本地 |

> **关于模型**：聊天栏右上方的模型下拉里，默认项是"跟随配置（你的默认模型）"。不选就沿用 `config.toml` 里的 `model`；也可以在下拉里直接挑别的模型（如 `gpt-5.1-codex`、`o3`、`claude-opus-4-5` 等），只对这一工作台生效，不会改你 Codex 的全局配置。选中的模型会作为 `codex exec -m <模型>` 传给真 Codex。

## 四、注意事项（如实说明）

1. 布局开在**独立浏览器窗口**，不是替换 Codex 应用窗口——Codex 官方应用不提供改自身布局的扩展点。聊天框接的就是真 Codex（`codex exec`），等价 CodeBuddy 右栏。
2. 聊天是"每轮一个完整回合"，不是逐字流式；需要交互审批的操作建议留在 read-only / workspace-write 档位。
3. 终端用了 win32-x64 原生模块（x64 Node 已验证可用）；换到 arm64/32 位 Node 时终端栏会提示 node-pty 不可用，其它功能正常。
4. 服务只监听 `127.0.0.1` 并带随机 token（首次访问写入 Cookie），文件访问被限制在项目根目录内。
5. **Windows 下不会弹出命令行黑框**：git 刷新、定时任务、终端开关、聊天会话拉起的子进程都隐藏窗口；打开浏览器用 `rundll32`（不再用 `cmd /c start`），关闭终端也不再额外 fork 一个 node 进程。若仍看到黑框，多半是插件缓存里还在跑旧版，按上面的「缓存更新」章节刷新并重启服务。
6. 想验证安装是否完好，跑 `node plugins/codex-codebuddy-workbench/scripts/smoke.mjs`：它在临时目录里造一个隔离的 git 仓库与假 codex，起停独立服务，逐项检查 HTTP / WebSocket / git / 终端 / 聊天，结束时自动清理，不改你的项目和 Codex 配置。

## 五、浏览器自动化工具（browser.mjs）

插件里附带一个**零依赖**的 Chromium 驱动（`plugins/codex-codebuddy-workbench/browser.mjs`）。它不用装 `playwright` 包、也不依赖浏览器类 MCP，就能让 AI / 脚本自己开浏览器、跑 JS、点按钮、截图、取网页源码。Chromium 会自动从本机 `ms-playwright` 目录探测；若探测不到，可用环境变量 `BROWSER_MJS_CHROME` 指定 chrome 路径。

```bash
node plugins/codex-codebuddy-workbench/browser.mjs start                        # 启动无头浏览器
node plugins/codex-codebuddy-workbench/browser.mjs open "http://127.0.0.1:5399/"  # 打开页面
node plugins/codex-codebuddy-workbench/browser.mjs screenshot out.png            # 截图
node plugins/codex-codebuddy-workbench/browser.mjs stop                          # 关闭
```

> 这是给 AI / 脚本用的"手和眼"，和工作台里给人看的预览窗口是两回事、互不冲突。
